## 上一版的问题

- 分色由通用曲线切割决定，与屋顶、翅膀、布片等物件结构脱节。
- 缩放到相同包围盒无法统一视觉重量；宽面物件、细长物件应有光学校正。
- 按路径长度保留细节会留下局部外轮廓，却删除较短的语义结构。
- 只保留上游几何骨架再圆角化，不能得到参考图标的圆润、自然、层叠关系。
- 自动统计和局部抽查验证了资产可用性，未建立整组造型验收。

## 这组的具体约束

1. **先让部件成立。** 每块颜色都可说出它是什么：鸟翼、果帽、门窗、伞布、靠垫、口袋、外焰。没有语义的切面不要加。
2. **轮廓饱满、转折柔和。** 轻微不对称来自生长方向或物件结构，不来自随机扰动。
3. **一个主关系。** 每枚优先表达一个前后／包裹／承托关系，最多加一个辅助关系。色块数量不必一样。
4. **三色各司其职。** 沿用项目三色，浅色用于部件与前层，主色承担主体或后层，深色用于结构线和识别点。配色不代替造型。
5. **细节必须有用。** 整体用 1.1 的细线，通常 1–3 组。眼睛、包扣可以用小实心形状；不为了装饰增加斑点。
6. **按视觉重量修正尺寸。** 24 单位画布是边界，不是统一撑满的目标。将整组在 26px、56px、浅深背景同时看，检查是否有个别过重或过淡。

## 检查范围与已修正问题

- 检查原始 XML、三色 token、曲线极值与描边边界。
- 浏览器中并列查看同色、同尺寸的新旧版本，以及 26px 和深色状态。
- 26px 深色检查发现原配色主体过暗；对照页将两列统一调整为 surface #746188、back #af94ca、detail #efdcfa，已同步到正式 lavender 深色主题。
- 分组联系表逐枚检查26px和56px；深色预览检查物件组与状态标记。工程检查不代替审美反馈。
- 交叉检查修正：球面拼片、橄榄球轮廓、人物双腿、齿轮徽标、4K/SD识别、录制实心点、顶部加行方向和多个同义变体重复。
- 设计账本：`design/redesign/catalog.json`。自查和交叉审查：`design/redesign/notes`。
- 六种 weight 延续既有派生规则；它们不是六套分别重画的上游风格。
